# 把 ESP32 接进来：让电脑和手机都能遥控它

先说结论，因为它决定了后面所有细节：

> **ESP32 不连手机，也不连互联网。它只和这台电脑说话。**
> 手机打开的是电脑上的页面，手机点一下 → 电脑收到 → 电脑通知板子。
> 电脑是那个「唯一的枢纽」。

这不是偷懒，是三条实际原因：

- **手机浏览器会拦跨域请求。** 让手机页面直接去敲 `http://192.168.1.66`，
  浏览器会先发一个预检请求，板子上就得实现 CORS。多写的每一行固件都是
  以后会变砖的地方。
- **板子不用暴露在公网。** 只有电脑能命令它，外部设备连它的机会都没有。
- **换手机不用重配。** 家里来客人想开个灯，给他开个 token 就行，
  不用再教他装 App、也不用往板子里塞第二份白名单。

```
   手机 ──HTTPS/HTTP──┐
                      ├──> 电脑（饺子，8787）──HTTP──> ESP32（80）
   平板 ──────────────┘            ↑                    │
                                   └──UDP 8789 发现──────┘
   AI（本地模型）──工具调用──┘
```

## 一、你需要什么

| 东西 | 说明 | 大概价 |
|---|---|---|
| ESP32 开发板 | ESP32-WROOM-32 DevKit 最常见，Type-C 口的那种 | 15–30 元 |
| 继电器模块 | 1/2/4 路都行；**带光耦隔离**的更安全 | 5–15 元 |
| 杜邦线 | 母对母 3 根起 | 2 元 |
| 5V 电源 | 板子的 USB 口供电就够（继电器多的话单独给 5V） | — |
| 要控制的东西 | 台灯、风扇、鱼缸泵…… | — |

⚠️ **强电警告**：继电器输出侧接的是 220V。断电作业、别用裸线、
别把继电器当总闸。不确定就去买个成品智能插座拆开看人家怎么做的。
第一次调试**只接低压**（比如一个 LED + 电阻），确认逻辑对了再碰强电。

## 二、三步跑通

### 第 1 步：烧固件

1. 装 [Arduino IDE](https://www.arduino.cc/en/software)，在「首选项 → 附加开发板管理器网址」
   里加上 `https://espressif.github.io/arduino-esp32/package_esp32_index.json`。
2. 「工具 → 开发板管理器」搜 `esp32`，装 **esp32 by Espressif**。
3. 打开仓库里的 `firmware/esp32/jiaozi_esp32.ino`。
4. 改文件开头这四行：

```cpp
const char* WIFI_SSID = "你家的WiFi";      // 2.4G！ESP32 不支持 5G
const char* WIFI_PASS = "密码";
const char* DEV_ID    = "esp32-jiaozi01";  // 全屋唯一，定了别再改
const char* DEV_NAME  = "客厅灯";           // 电脑上显示的名字
```

5. 开发板选 `ESP32 Dev Module`，选对串口，点上传。
6. 打开串口监视器（**115200**），看到：

```
[wifi] 已连上 MyWiFi  IP=192.168.1.66
[net] 已在喊话，电脑上打开「家电」应该能看到我了
```

看到 `IP=` 就成功了。

> **一句话说明它为什么不掉线**：固件里没有长连接、没有心跳、没有重连状态机。
> 它只是每秒喊一声「我是谁」。断电、拔网线、重启路由器之后，
> 再通电三秒内电脑就会重新看到它。少一个状态，就少一类 bug。

### 第 2 步：电脑上搜到它

```bash
python3 -m jiaozi --host 0.0.0.0    # 注意 --host，否则手机连不上
```

打开桌面 → **家电** → 点「搜索设备」。板子会出现在列表里，显示名字、IP、在线状态和每一路开关。

搜不到就用「手动添加」填它的 IP（串口里那个 `192.168.1.66`）。
**公共 WiFi 常禁组播，发现不到不代表连不上** —— 手动填一定能通。

### 第 3 步：手机上遥控

手机连**同一个 WiFi**，浏览器打开：

```
http://192.168.1.47:8787/?token=你配置里的token
```

（`192.168.1.47` 是电脑的局域网 IP，启动时终端会打印；也可以跑
`python3 tools/doctor.py` 直接看。）

打开「家电」，点开关。**和电脑上是同一批开关、同一个状态**——
因为手机点的也是那台电脑。

> 手机上打不开？先跑 `python3 tools/doctor.py`，它会直接告诉你
> 是「只监听回环」还是「防火墙没放行」。Windows 上放行一次：
> 管理员 PowerShell 里 `powershell -ExecutionPolicy Bypass -File scripts\win-firewall.ps1`。

## 三、接线

### 继电器 → ESP32

| 继电器模块 | ESP32 | 说明 |
|---|---|---|
| VCC | 5V（或 3V3） | 看模块标注；光耦版通常要 5V |
| GND | GND | 必须共地 |
| IN1 | GPIO 26 | 对应固件里的 `r1` |
| IN2 | GPIO 27 | 对应 `r2` |

**GPIO 别乱选**，这几类会坑人：

| 引脚 | 坑 |
|---|---|
| 6–11 | 接 Flash，用了直接起不来 |
| 0 / 2 / 12 / 15 | 启动时决定启动模式，上电瞬间被拉低会进不了系统 |
| 34–39 | 只能输入，驱动不了继电器 |
| 26 / 27 / 25 / 32 / 33 | ✅ 随便用 |

固件里 `CH[]` 数组改引脚就行：

```cpp
Channel CH[] = {
  { "r1", "灯",   "relay", 26, true,  false },   // true = 低电平触发
  { "r2", "风扇", "relay", 27, true,  false },
};
```

`active_low = true` 对应市面上大多数蓝色继电器模块（IN 给低电平吸合）。
**接反了不会烧，只是开关变成倒的** —— 打开变关、关变开，改成 `false` 即可。

### 要控制红外（电视、空调）

固件现在只做继电器。红外要 38kHz 载波，推荐在 Arduino 里再装
`IRremoteESP8266`，在 `/api/cmd` 里加一个分支：

```cpp
if (action == "ir_send") { irsend.sendRaw(rawData, rawLen, 38); }
```

电脑这边不用改——`esp_control` 的 `action` 字段本来就是透传给设备的，
AI 说「把空调调到 26 度」时会带 `action`，固件认哪个就用哪个。

## 四、没有硬件？先跑模拟器

板子还在路上也能把整条链路跑通，看到的界面和真板子一模一样：

```bash
# 一台两路的「客厅灯」
python3 tools/esp_sim.py --id esp32-a1b2 --name 客厅灯 --channels r1:灯,r2:风扇 --http-port 8899

# 再开一台（同一台机器上多开要加 --no-listen，避免抢 8789 端口）
python3 tools/esp_sim.py --id esp32-c3d4 --name 卧室空调 --channels r1:空调 \
        --http-port 8901 --key 1234 --no-listen
```

模拟器会把自己收到的命令打印出来：

```
[客厅灯] 收到命令 {"channel": "r1", "on": true} → {"r1": true, "r2": false}
```

一边点界面一边看这行字，就知道「到底是界面没发、还是设备没收到」。

## 五、让 AI 动手

接进来之后不需要额外配置，模型直接就能开：

> **你**：把客厅灯打开
> **饺子**：（调 `esp_devices` 看到「客厅灯 r1/r2」）→ 调 `esp_control`
> → 「客厅灯已打开。」

三个工具：

| 工具 | 作用 |
|---|---|
| `esp_devices` | 列出设备、在线状态、每一路叫什么 |
| `esp_state` | 读某台的开关状态和传感器 |
| `esp_control` | 开关某一路；`toggle` 切换；`action` 给红外类设备 |

规则写在系统提示里：

- 多路设备必须指定 `channel`，一路的可以省略；
- 设备离线就直说离线（可能断电或不在同一个 WiFi），**不许假装成功**；
- 拿不准是哪台时先问人 —— 开错的是别人家的电器。

> 想关掉 AI 的动手权限：配置里 `esp.ai_control = false`。
> 界面上的开关照常能用，只是模型不能碰。

## 六、协议（想自己写固件的话）

三条接口，全是 JSON，没有鉴权也可以，设了 `JZ_KEY` 就带 `X-JZ-Key` 头。

### `GET /api/info` —— 你是谁

```json
{"ok": true, "data": {
  "id": "esp32-a1b2", "name": "客厅灯", "model": "esp32", "fw": "1.0",
  "proto": 1, "ip": "192.168.1.66", "port": 80,
  "caps": ["relay", "sensor"],
  "channels": [{"id": "r1", "name": "灯", "type": "relay"}]
}}
```

### `GET /api/state` —— 现在什么状态

```json
{"ok": true, "data": {
  "channels": {"r1": {"name": "灯", "type": "relay", "on": true}},
  "sensors": {"temp": 24.5},
  "uptime": 3600, "rssi": -52
}}
```

### `POST /api/cmd` —— 动手

```json
{"channel": "r1", "on": true}      // 开
{"channel": "r1", "on": false}     // 关
{"channel": "r1", "toggle": true}  // 切换
{"action": "ac_26"}                // 自定义动作，固件自己解释
```

回 `{"ok": true, "data": {"channel": "r1", "on": true, "channels": {...}}}`。

### 发现包（UDP 8789）

设备每秒广播/组播一次：

```json
{"proto": 1, "t": "esp.announce", "id": "esp32-a1b2", "name": "客厅灯",
 "port": 80, "ip": "192.168.1.66", "caps": ["relay"], "channels": [...]}
```

电脑搜设备时发 `{"proto":1,"t":"esp.find"}`，设备**单播回**给发起者。
`proto` 对不上会被丢弃并打一行日志——不会把畸形数据混进状态表。

## 七、出问题了按这个查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 电脑上搜不到 | 板子不在同一网段 / AP 隔离 / 组播被禁 | 串口看 IP；用「手动添加」填 IP 一定能通 |
| 能添加但显示「离线」 | 电脑访问不到板子的 80 端口 | 浏览器直接开 `http://<板子IP>/api/info`，开不了就是网络问题 |
| 列表里一闪一闪 | 2.4G 丢包 | 正常，`ANNOUNCE_MS` 已 1 秒；把板子挪近路由器 |
| 点开关没反应 | 继电器接线 / 电平反了 | 换成 `active_low` 试试；用万用表量 IN 脚有没有跳变 |
| 开起来是反的 | 低电平触发模块用了 `active_low=false` | 改成 `true` |
| 显示「设备返回 401」 | 固件设了 `JZ_KEY`，电脑上没填 | 在「家电 → 更多 → 删除」后重新「手动添加」，填上密钥 |
| 手机能开页面但家电是空的 | 手机连的不是电脑 | 家电数据存在电脑上；确认手机打开的是电脑的 IP |
| 板子反复重启 | 继电器线圈电流把电压拉垮 | 继电器单独 5V 供电，和板子共地 |
| 上传固件失败 | 没按 BOOT / 串口驱动没装 | 按住 BOOT 再点上传；装 CH340 或 CP210x 驱动 |

## 八、安全，说清楚

- **只在局域网内。** 电脑不对公网开端口；板子也不对公网开。
- **密钥可选但建议设。** 设了之后同 WiFi 的其他人也不能随便开关你家电器。
  密钥存在 `~/.jiaozi/esp.json`，和配置分离，方便单独备份/清除。
- **AI 能碰到的就是这几路开关。** 它读不到你的文件、跑不了命令
  （那是另外的工具，且危险操作要人确认）。
- **别把加热器、大功率电器直接接继电器。** 继电器标 10A 不代表长期跑 10A 安全。
  这类负载要么加接触器，要么就买成品。
- **公用 WiFi 上别开。** 你在咖啡馆开的桌面，同一网段的人可能也扫得到。
