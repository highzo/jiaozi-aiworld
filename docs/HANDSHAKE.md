# 真机互通：三步，每步都有「应该看到什么」

这是给两台真实设备联调用的——比如电脑 + 手机，或者家里两台电脑，
或者电脑 + 树莓派。**每一步都写清楚了「正常长什么样」和「不正常怎么办」**，
跑完把卡住的那一步和它的输出发出来就够了，不用描述现象。

先在两台机器上都确认一遍：

```bash
python3 tools/doctor.py
```

看到 ❌ 就先解决它。最常见的一条是 **「只监听回环」**——
那是因为启动时没加 `--host 0.0.0.0`，别的机器永远连不上。

---

## 第 1 步：手机能打开桌面

**在电脑上**（注意 `--host`）：

```bash
python3 -m jiaozi --host 0.0.0.0
```

终端会打印类似：

```
==============================================================
  饺子AIWorld  v0.1.0
  打开:  http://192.168.1.47:8787/
  手机/平板: http://192.168.1.47:8787/?token=UFyBTikZ5w1xwE
  局域网互认: 已开启（客厅电脑，UDP 8788）
  家电发现: 已开启（UDP 8789，找不到就手动填 IP）
==============================================================
```

**在手机浏览器**里打开那行 `?token=` 的地址。

✅ **正常**：桌面出来了，图标、任务栏、搜索框都在。

❌ **卡住的话，对照这张表**：

| 手机看到 | 说明 | 怎么办 |
|---|---|---|
| 一直转圈/超时 | 连不到端口 | 电脑上 `doctor.py` 看是不是只监听回环；两个设备是不是同一个 WiFi（很多路由器有 2.4G/5G 两个名字，是**不同网段**） |
| `{"ok": false, "error": "未授权"}` | 地址里没带 token 或带错了 | 复制终端打印的完整地址，别漏 `?token=` |
| 连接被拒绝 | 防火墙挡了 | Windows 管理员运行 `powershell -ExecutionPolicy Bypass -File scripts\win-firewall.ps1`；Linux `ufw allow 8787/tcp` |
| 打开了但白屏 | 静态文件没加载 | 电脑上直接开 `http://127.0.0.1:8787/` 对比；F12 看 Console |
| 打开了，但 AI 不回复 | 模型没配 | 这是下一步的事，先确认桌面能用 |

---

## 第 2 步：两台机器互相看得见

在电脑 A 上：**设备 → 生成配对码**，屏幕上出现 6 位数字和倒计时。

在电脑 B（或手机）上：**设备 → 填 A 的 IP 和端口 8787 → 填那 6 位数字 → 配对**。

✅ **正常**：A 出现在 B 的列表里，带「已配对」标签；B 那边也刷新出 A。
两边都能看到对方的设备名、IP、平台（Windows/Linux/安卓）。

❌ **卡住的话**：

| 现象 | 说明 | 怎么办 |
|---|---|---|
| 列表里根本看不到对方 | 组播被禁（公共 WiFi 常见） | **不影响**，手填 IP + 配对码一样能通 |
| 填了 IP 点配对，提示「连不上」 | 对端端口不通 | 在对端跑 `doctor.py`；浏览器直接开 `http://<对端IP>:8787/api/peer/hello`，能出 JSON 才算通 |
| 提示「配对码不对/已过期」 | 码 5 分钟过期、一次性 | 重新生成一个，手快点 |
| 提示「试错次数过多」 | 连续输错 6 次 | 对端重新生成，码会重置计数 |
| 配对成功但显示离线 | 心跳包丢了 | 两边在同一网段吗？跨网段（比如一个连 5G 一个连 2.4G 的不同 SSID）不行 |

配对成功后验证一下「真的能指挥」：在 B 上打开 **AI 面板**，说

> 在对方的机器上打开终端

AI 会调 `peer_list` 找到 A、再用 `peer_call` 在 A 上执行 `ui_open`。
**A 的屏幕上会真的弹出一个终端窗口。**

---

## 第 3 步：让 AI 跨设备干活

这一步不加新功能，只是把第 1、2 步串起来，确认整条链路没有断点：

1. 手机打开桌面（第 1 步）
2. 手机上的 **设备** 里能看到电脑（第 2 步）
3. 手机上问 AI：「**在电脑上看看下载目录有什么**」

✅ **正常**：AI 先 `peer_list`，再 `peer_call` 到电脑上 `fs_list`，
手机上直接显示电脑下载目录的文件名。

如果 AI 说「没有已配对的设备」——回第 2 步。
如果 AI 说「连不上」——去电脑上 `doctor.py`。

---

## 跑完把这几样发出来

出问题的时候，这三样最有信息量（比描述现象有用一百倍）：

```bash
# 1. 体检报告
python3 tools/doctor.py

# 2. 服务端启动那一段（前 12 行）
python3 -m jiaozi --host 0.0.0.0 2>&1 | head -12

# 3. 打不通的那个接口，直接敲一次
curl -s http://<对端IP>:8787/api/peer/hello
```

有了这三样，基本能一眼定位是网络层、鉴权层还是应用层。

---

## 附：为什么会有「发现不了但能连上」

局域网发现靠的是 **UDP 组播/广播**。两件事会让它失效：

- **AP 隔离**：很多商用/酒店 WiFi 默认隔离客户端，互相完全不可见。
- **组播被丢**：2.4G 上本来就丢包，某些路由器干脆不转发 `239.255.x.x`。

所以设计上一开始就留了「手填 IP + 配对码」这条路。
**发现只是省一次手输，不是唯一通路。** 这也是为什么
`doctor.py` 里「互认发现 :8788 空闲」只是 ✅ 而不是必须。
