# 语音：说一句，它就去做

麦克风只在两种时候打开：**你按下去的时候**，或者**你明确打开「一直听」的时候**。
没有后台常驻监听，没有偷偷上传。

```
浏览器麦克风 ──WebAudio──> 16k 单声道 WAV（就在页面里编码）
                              │
                       POST /api/voice/asr
                              │
              ┌───────────────┴───────────────┐
        sherpa-onnx（本地）            任意 OpenAI 兼容转写接口
        音频不出这台机器               whisper.cpp / vLLM / OpenAI
```

---

## 一、为什么在浏览器里编码 WAV

服务端要接的是裸 PCM，浏览器最原始的麦克风数据本来也是裸 PCM。
在页面里拼一个 44 字节的 WAV 头，服务端就**不需要 ffmpeg、不需要解码库**——
这是能守住「只依赖 Python 标准库」的关键。

代价是：音频在发送前要先攒够一句（默认说完静音 1.2 秒才发），
所以不是逐字上屏的实时识别。换来的是一条没有任何本地依赖的链路。

## 二、配一个后端（二选一）

### A. 本地识别（推荐，音频不出机器）

需要 `sherpa-onnx`，它是第三方包——**这是整个项目唯一允许的可选依赖**，
不装它就自动退回 B 或关闭麦克风，不影响其它任何功能。

```bash
pip install sherpa-onnx

# 下载中文模型（约 230MB，SenseVoice 小模型，识别质量够用）
mkdir -p ~/models/sense-voice && cd ~/models/sense-voice
# 从 https://github.com/k2-fsa/sherpa-onnx/releases 的
# sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17 之类目录里下载并解压，
# 确认目录里至少有：model.onnx  tokens.txt
```

然后：**设置 → 语音 → 本地识别模型目录** 填 `~/models/sense-voice`，保存。

顶部那块状态会变成：

```
麦克风可用 · 本地识别
本地识别，音频不出这台机器
唤醒词：饺子
```

### B. 远程转写接口

任何实现了 `POST /v1/audio/transcriptions`（multipart，字段名 `file`）的服务都行：

| 服务 | base_url 填什么 |
|---|---|
| whisper.cpp 的 `server` | `http://127.0.0.1:8080/v1` |
| vLLM + whisper | `http://127.0.0.1:8000/v1` |
| OpenAI | `https://api.openai.com/v1` |
| SiliconFlow 等兼容服务 | 按它文档里的 `/v1` |

填 **设置 → 语音 → 或者：远程转写接口**，有 key 就填 key。

> 两个都填了？**本地优先**。判断依据始终显示在面板顶部，不用猜。

## 三、怎么用

| 动作 | 结果 |
|---|---|
| 点一下麦克风 | 开始听；说完停顿 1.2 秒自动结束并执行 |
| 再点一下 | 立刻停止并发送 |
| 右键麦克风 | 打开菜单：开/关「一直听」、当前唤醒词、用的哪个后端 |

**「一直听」**：麦克风常开，但只有说到唤醒词的那句话才会被执行，
其它当闲聊丢掉（会显示听到了什么，方便你确认它真的在听）。

唤醒词默认 `饺子`，可以改成任何词：**设置 → 语音 → 唤醒词**。

说「饺子，把客厅灯打开」→ 唤醒词被剥掉 → 执行「把客厅灯打开」。

## 四、它现在做不到什么（先说清楚）

- **不是逐字实时上屏。** 一句话说完才出结果。
- **不是声纹识别。** 谁说话都算，别指望它认人。
- **唤醒词不是离线热词检测。** 它是「整句识别完之后看开头有没有这个词」，
  所以一直听的时候，没唤醒的句子也会被识别（但不会执行）。
  真正省电的 KWS 要做 VAD + 小模型，这一版没做。
- **手机上不锁屏才能一直听。** 浏览器休眠会停掉麦克风，这是浏览器的限制。

## 五、出问题了

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 输入框旁边没有麦克风 | 没有可用后端 | 设置 → 语音，看顶上那块状态写的是什么 |
| 「麦克风不可用 · 不可用 没配 voice.model_dir」 | 本地模式缺模型目录 | 填目录，或改用远程接口 |
| 「没装 sherpa-onnx（ModuleNotFoundError）」 | 装了模型没装包 | `pip install sherpa-onnx` |
| 点了没反应 | 浏览器禁止麦克风 | 地址栏左边的小锁 → 允许麦克风；`http://` 之外的地址必须是 `https` 或 `localhost` |
| 「打不开麦克风」 | 系统层面被占用/被拒 | 关掉正在录音的其它程序；手机上检查权限 |
| 一直是「没听清」 | 太短、太吵、离太远 | 说完稍等一下；离麦克风近点 |
| 识别出来是英文/乱码 | 模型语言不对 | 设置里 `voice.lang` 填 `zh`，或换中文模型 |
| 手机上完全没声音 | 不是 https 也不是 localhost | 手机通过 `http://192.168.x.x` 打开时，浏览器会禁用麦克风。用 `adb reverse`、或者给电脑配个自签 https |

> 最后一条是浏览器硬性规定（Secure Context），不是我们的 bug。
> 想在手机上用语音，最省事的办法是用 `adb reverse tcp:8787 tcp:8787`
> 然后手机访问 `http://localhost:8787`。

## 六、接口

### `GET /api/voice/status`

```json
{"ok": true, "data": {
  "backend": "sherpa",     // sherpa | http | mock | none
  "ready": true,
  "local": true,
  "hint": "本地识别，音频不出这台机器",
  "wake": "饺子",
  "always_listen": false
}}
```

`ready=false` 时前端**不显示麦克风按钮**——一个按了没反应的按钮比没有更糟。

### `POST /api/voice/asr`

请求体（音频用 base64，和文件上传走同一套约定）：

```json
{"wav": "UklGRiQAAABXQVZFZm10IBAAAA..."}
```

返回：

```json
{"ok": true, "data": {
  "text": "把客厅灯打开",
  "backend": "sherpa",
  "seconds": 1.84,
  "ms": 320
}}
```

只接受 **16 位 PCM 单声道 WAV**。位深不对、不是 PCM、超过 120 秒，
都会明确报错而不是返回空字符串——「识别为空」和「音频不合法」
是两种完全不同的故障，不能混成一个。
