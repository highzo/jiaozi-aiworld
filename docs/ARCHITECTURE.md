## 为什么用浏览器做渲染层

三种目标设备（x86 电脑、安卓手机、ARM 开发板）唯一的公共 UI 运行时就是浏览器内核。

| 方案 | 电脑 | 安卓 | 开发板 | 手机远程接入 |
|---|---|---|---|---|
| X11 + 原生 Qt/GTK | 好 | 需 proot + X server，脆弱 | 需驱动/合成器，分辨率一变就崩 | 要 VNC，体验差 |
| Wayland 合成器自研 | 好 | 基本不可行 | 需要 GPU 支持 | 要额外串流 |
| **浏览器渲染 + 本地服务** | 好 | 原生 | Chromium 已有现成支持 | 天然支持，同一 URL |

代价说清楚：拿不到原生 GPU 加速的窗口合成，跑不了 X11 应用。换来的是"一套 UI 三端一致"。

## 数据流

### 请求（人 → 系统）

前端 `JZ.api.get/post` → `/api/*` → 具体模块 → JSON。
所有写操作成功后向 EventBus 发一个事件，例如 `fs_change`。

### 事件（系统 → 所有客户端）

```
GET /api/events          一次长连接，所有客户端订阅同一总线
  data: {"t":"term","id":"ab12","d":"bash-5.3$ "}
  data: {"t":"fs_change","d":{"path":"/home/pi/a.txt","action":"write"}}
  data: {"t":"notify","d":{"title":"...","body":"..."}}
  data: {"t":"ui","d":{"action":"open","app":"files","path":"/home/pi"}}
```

用 **chunked transfer** 而不是 `Content-Length`，因为 SSE 是无限流。
`?ms=1500` 可以让流在 1.5 秒后自行结束（截图 / 一次性抓取 / 调试用）。

每个客户端一个 `queue.Queue(maxsize=2000)`。慢客户端丢最旧的事件，**绝不阻塞内核**——
开发板上一个卡住的浏览器标签不能拖垮整个服务。

### 多客户端 = 同一个桌面

窗口是每个客户端自己的（各自的 DOM），但**状态是共享的**：

- 文件系统共享（本来就是同一份）
- AI 会话共享（`sid` 相同的上下文）
- 剪贴板、通知、壁纸共享
- AI 的 `ui_open` 广播给所有客户端 → 每台设备上都会弹出那个窗口

这是"人和 AI 共用一张桌子"在工程上的落地方式：不是让 AI 模拟点击，
而是让 AI 调用和 UI 完全相同的接口，再由事件总线把结果铺到每一块屏幕上。

## Agent 循环

```
用户输入
   │
   ├─ 追加 user 消息
   ├─ 组装 messages（system + 最近 N 条，工具结果超长截断）
   │
   ▼
┌──► LLMClient.chat(stream=True)
│      │  delta.content → 事件流（前端逐字显示）
│      │  增量拼装 delta.tool_calls
│      ▼
│   有 tool_calls ?
│      │ 否 → 结束，返回最终文本
│      │ 是
│      ▼
│   对每个 call：
│      ├─ 工具名不存在 → 回填错误文本
│      ├─ 需要审批？ ── 是 → 发 approval 事件 → 阻塞等人（默认 300s 超时=拒绝）
│      ├─ tools.dispatch()  → 真实执行（和 UI 同一套函数）
│      └─ 结果回填：原生协议用 role=tool；提示协议用 role=user 的【工具结果】
│
└── 步数 +1，未超过 max_steps 就继续
```

### 双协议

| | 原生 function calling | 提示协议 |
|---|---|---|
| 触发 | `native_tools: true` | `false`，或模型报错自动降级 |
| 模型要求 | 支持 `tools` 参数 | 只要能输出 JSON |
| 消息结构 | assistant.tool_calls + tool 消息 | 纯文本 + 【工具结果】前缀 |
| 适合 | Qwen2.5-7B / DeepSeek / GPT-4 级 | 0.5B~3B 本地小模型 |

提示协议的解析器做了容错：抓 ```json 代码块，也抓裸 JSON；单引号会尝试修复；
解析失败就当普通回复，不会把整个会话卡死。

### 审批为什么不放在前端做

审批状态在服务端 `AgentSession.pending` 里，是一个 `threading.Event`。
Agent 循环所在线程阻塞等待，HTTP 请求线程收到 `/api/agent/approve` 后 set 事件。
这样即使前端刷新页面、换一台设备点"允许"，循环也能继续——审批是会话级的，不是页面级的。

## 终端

三层：

1. **PTY**：POSIX 上 `pty.fork()` + `TIOCSWINSZ`，子进程以为自己在真终端里（`ls` 有颜色，`top` 能画界面）。
2. **环形缓冲**：每个会话保留最近 96KB 原始输出。断线重连时前端拉 `/api/term/buffer` 整体重建，
   不丢历史；页面刚打开时 shell 已经吐出的那几行也能补回来。
3. **VT 解析**（`js/vt.js`，独立模块）：字符网格 + SGR 状态机 + 光标控制 + 宽字符占两格。
   渲染时按样式合并 run，减少 `<span>` 数量。

不支持：滚动区域（CSI r）、鼠标上报、字符集切换。所以 `vim`/`htop` 会画歪，
`bash`/`git`/`make`/`python`/日志没问题。这是有意的取舍——真需要全屏 TUI 时，
用 SSH 或者以后加 xterm.js 作为可选渲染器。

宽字符处理很关键：中文文件名在 `ls` 里如果按 1 格算，整行会错位。这里对
CJK / 韩文 / 全角 / 常用 emoji 做了双宽处理，第二个格子存空字符占位。

## 沙箱

```
path → 展开 ~ 和环境变量 → resolve() → 必须落在 roots 之一内部（含子目录）
                                   → 否则 403
```

- `roots` 默认 `["~"]`，设置页可以加（例如 `/sdcard`、`/data`）。
- 删除不真删，移动到 `~/.jiaozi/trash/时间戳-文件名`。
- 上传走 base64 JSON（不写 multipart 解析器），单文件上限可配，默认 64MB。

这不是安全边界，只是**防手滑**。真正的隔离要靠容器/用户权限。

## 性能

目标：树莓派 4 / 4G 内存上能用。

- 后端零依赖，常驻内存约 30MB（不含模型）。
- 前端无框架、无构建，首屏 8 个文件，总共约 120KB 未压缩。
- SSE 事件很小（终端按 64KB 块切分），局域网延迟可忽略。
- 窗口用 `contain: layout paint` 隔离重排；拖拽用 transform 期间不触发全局布局。
- 终端渲染用 rAF 节流 + 150ms 兜底定时器（后台标签页 rAF 会停）。

## 已知失败模式

| 现象 | 原因 | 处理 |
|---|---|---|
| 模型一直转圈 | 端点不通 / 被系统代理劫持 | 本机与局域网地址会**绕过代理**直连；云端地址才走代理 |
| 小模型反复调用同一个工具 | 上下文里没看清结果 | 降 `max_steps`，或换 3B 以上模型 |
| 终端中文错位 | 用了非等宽字体 | 装 JetBrains Mono / Noto Mono |
| 板子上页面卡 | 无 GPU，backdrop-filter 太重 | 深色主题 + 减少窗口数量；可在 CSS 里关掉毛玻璃 |
| 安卓后台被杀 | 系统省电策略 | `termux-wake-lock`，并把 Termux 加入电池白名单 |

## 实测踩到的坑

下面每一条都是测试真跑出来的，不是设计时想到的。留在这里，因为它们是这个架构的真实成本。

**1. SSE 用 `Content-Length` 会挂住**
一开始想给流式响应算长度，结果浏览器永远等不到"结束"。改成 chunked transfer 才对——
流式响应本来就没有确定的结尾。

**2. 系统代理会劫持 127.0.0.1**
本机 Ollama 请求莫名 502，抓包才发现走的是公司的 HTTP 代理。`urllib` 默认读环境变量，
所以对 `localhost / 127.0.0.1 / 192.168.* / 10.*` 一律换成空 `ProxyHandler({})` 直连。
这个坑在国内办公网络里几乎必踩。

**3. 终端按键会串位（`echo` 变成 `ecoh`）**
每个按键独立 `fetch`，HTTP/1.1 下并发请求落在不同 TCP 连接上，到达顺序没有保证。
UI 测试里一次敲 19 个字符，服务端日志显示同一秒进了 **18 个并行请求**。
修法是前端做单通道队列：同一时刻只允许一个请求在途，期间的按键合并成一批再发。
副作用是请求数从 18 降到 2，对开发板是白赚的。

**4. 新终端一片空白**
管道模式的读取是"攒到换行才发"，而 shell 的提示符 `bash-5.3$ ` **不带换行**——
所以刚打开终端什么都没有，用户以为没启动。桌面测试没发现，因为测试紧跟着就敲了命令，
换行把提示符一起冲出来了。改成按块读、拿到就发、用增量解码器处理被切开的 UTF-8。

**5. 手机上文件名整个消失**
文件管理器侧栏固定 176px，390px 屏幕下把 `1fr` 的名称列压成 0 宽，只剩图标和时间。
测试原本只断言"列表有内容"，行数是对的，所以看不出来——是看截图看出来的。
窄屏改成顶部一排可横滑的快捷入口 + 只保留"名称/修改时间"两列，并把"文件名可见"
写成了带真实宽度测量的断言。

**6. 手机首屏是个聊天框**
AI 面板窄屏下是全屏的，默认展开就把桌面整个盖住。第一眼看到的不是"人机共用的桌面"，
而是"又一个聊天 App"——把产品最核心的东西藏没了。改成窄屏默认进桌面，
并在面板右上角给一个带"桌面"字样的出口。

**7. 刷新页面就刷屏报错**
浏览器关标签会让 `socketserver` 抛 `ConnectionResetError` 堆栈。开发板上这些日志会把
存储写满。重写 `handle_error` 静默掉断连类异常——断连是正常现象，不是故障。

**8. 后台标签页 rAF 不触发，终端不刷新**
SSE 事件到了、屏幕模型也更新了，但 `requestAnimationFrame` 在无合成环境里不跑。
加了一层 150ms 兜底定时器：`dirty` 还没清就直接画。

## AI 的手脚：图像生成为什么放在后端

`image_gen` 是 13 个工具里唯一"往外要东西"的：它调一个外部的文生图模型，
然后把结果**写进沙箱目录**，把路径交回给模型。

三个决定值得记下来：

**1. 不做成聊天窗口里的 base64 图片。**
如果把图片直接塞进消息气泡，它只存在于前端内存里——刷新就没了，别的程序也拿不到。
落到磁盘之后，同一张图可以：被文件管理器看到、被 `ui_open` 打开、被 `shell_run` 拿去 `scp` 上传、
被另一个视觉模型读回来。机器人没有浏览器，这一步是必须的。

**2. 复用 `llm` 的配置，但可以单独覆盖。**
大多数 OpenAI 兼容网关同时提供文本和图像端点，所以 `image.base_url`、`image.api_key`
留空就回落到 `llm`。本机跑 Ollama + 云端跑图像这种组合也能配。

**3. 前端要让人"看见"，不是让人读 JSON。**
工具结果是 `{"ok":true,"files":[...]}`，直接展示等于什么都没说。
所以 `step-card` 在检测到 `image_gen` 时会把 `files` 解析出来渲染成缩略图，点开进图片查看器。
图片查看器本身也支持直接打开一个**目录**——AI 经常把存图文件夹甩过来，这时当相册看才是对的。

这台机器上真实的端到端耗时：一句话 → AI 规划 → 两次工具调用 → 两张 832×1248 PNG，
**约 75 秒**，其中 90% 是图像模型自己的推理时间。

## 第二轮实测踩到的坑（接上真模型之后）

**9. Windows 上两个进程能同时监听同一个端口**
`SO_REUSEADDR` 在 Windows 上的语义和 Unix 完全不同：它允许第二个进程绑定一个**已经在监听**的端口。
于是"改完代码重启"其实启动了一个新进程，旧进程还活着，两个一起抢 accept——
请求随机落到旧代码上，表现为"改了没用"。最坑的是没有任何报错。
Python 的 `HTTPServer` 默认 `allow_reuse_address = 1`，正好踩中。
修法：Windows 上关掉 `SO_REUSEADDR`、改用 `SO_EXCLUSIVEADDRUSE`，并给端口占用一个人话错误提示。

**10. 脱敏后的 API Key 被原样提交回来，把真 Key 覆盖成星号**
`public_view()` 把 `api_key` 变成 `********` 返回给前端，前端又把它填进输入框的 `value`。
用户点一次"保存"，真实密钥就被八个星号替换，之后所有请求 401——而且界面上看起来一切正常。
两道防线：前端 `value` 留空只用 placeholder 提示"已设置"；后端 `save()` 里把空值和纯星号一律当作"不修改"。

**11. 一条 prompt 里写"第一张…第二张…"，模型画了张分屏**
想省一次调用，让 AI 传 `n=2` 并在一句话里描述两个场景。结果模型把两个场景**画进同一张画布**，
左右各一半，两张图长得一模一样。
这不是 API 的 bug，是提示词的问题：`n` 的语义是"同一画面的变体"，不是"不同场景"。
改回一次调用只描述一个画面、要几张就调几次，画质立刻正常。

**12. 白名单漏了一个键，配置静默丢失**
`/api/config` 有一层 `allowed` 字段白名单。加图像功能时忘了把 `image` 加进去，
于是设置界面里改图像参数、点保存、提示"已保存"——实际什么都没存。
是冒烟测试里"关闭图像后应该拒绝生成"这条断言把它抓出来的：开关关了还在花钱。
新增配置段时，**白名单和 DEFAULTS 必须同时改**。

## 第三轮实测踩到的坑（装进 WSL2，跑真 Linux）

实测环境：Windows 11 + WSL2 Ubuntu 24.04.5 LTS，服务完全跑在 Linux VM 里，
测试从 Windows 侧通过网络打过去（`JIAOZI_URL` 指向 `127.0.0.1:8787`，
端口由 `wslhost.exe` 转发）。终端拿到**真 PTY**（`tty: true`，`root@lucy:~#` 正常交互），
Windows 上那套管道模式的兼容分支在这里完全不触发。

**13. 一个匿名请求就能把"localhost 免 token"关掉，把自己锁在门外**
`allow_localhost` 的本意是：本机访问不必带 token。但 `POST /api/config`
在豁免生效时也是免鉴权的，于是本机任意一个**没有 token**的请求都能把豁免关掉。
关掉的瞬间，调用方自己、以及之后所有本机请求全部 401——
**连把它改回来的请求都需要 token，而你没有**。这是个不可逆的自锁。
Windows 上一直没暴露，因为测试读的是本机 `~/.jiaozi/config.json`，token 恰好对得上，
带 token 去关，自然成功；换成 WSL 后 token 不同，测试用错 token 去关，照样返回 200，
然后整段鉴权断言全红，才看见这个洞。
修法：关闭 `allow_localhost` 必须**自带有效 token**，否则 403 并说明原因。
"允许匿名做的事"里，不能包含"取消匿名权限"本身。

**14. root 的提示符是 `#`，而测试只认 `$` 和 `>`**
终端断言写的是 `"bash" in txt or "$" in txt or ">" in txt`。
普通用户提示符 `$`、Windows PowerShell 提示符 `>` 都能命中，
但 WSL 默认以 root 登录，提示符是 `root@lucy:~#`——一个 `#`，三种都不匹配。
缓冲区里明明有完整回显，断言却报"终端没有提示符"。
这类断言要按"提示符可能是 `$` / `#` / `>`"来写，别按自己习惯的那一种。

**15. 跨机器跑测试，token 和假模型地址都得跟着换**
测试是设计成"同机自测"的：token 从本机 `~/.jiaozi/config.json` 读，
假模型服务监听 `127.0.0.1:8799`，并把这个地址写进被测服务的 `llm.base_url`。
一旦服务在 WSL 里，这三件事全部错位：
- 读到的是 Windows 的 token，服务端不认 → 鉴权段全红
- `127.0.0.1:8799` 在 Linux 里指向 Linux 自己，连不上 → 9 项模型/图像断言全红
- 图片落盘检查用本机 `os.path.getsize()` 去 stat Linux 路径 → 全部 `-1`

现在三个都做成可配置：`JIAOZI_TOKEN`、`MOCK_BIND` / `JIAOZI_MOCK_URL`，
落盘检查改走服务端 `/api/fs/stat`（以服务端自己的视角为准，这才是要测的东西）。
WSL 里能连到 Windows 主机的地址是 `172.28.128.1`（`vEthernet (WSL)` 那头）。
一句话：**测试从本机自测变成远程验证时，"我以为的 127.0.0.1" 全部要重新问一遍"这是谁的回环"**。


## 局域网互认：为什么是组播，为什么是配对码

目标是「手机、电脑、机器人、ESP 互相调」，而且**不能要求用户懂 IP**。

**发现用 UDP 组播，不用 mDNS。** mDNS 的协议实现（Zeroconf）是第三方包，
而这个项目的立身之本是零依赖——一条 `pkg install python` 就能在 Termux 里跑。
组播只需要 `socket` 模块一百行：发一条 JSON 身份，收别人的 JSON，塞进内存字典。
每张网卡各发一遍，是因为多网卡机器（WSL 的 `vEthernet`、Hyper-V、VMware）
只往默认网卡发的话，另一半设备永远发现不了。

**配对用 6 位数字，不用密码。** 密码要传输、要存储、要记。配对码只要存在 5 分钟、
只用一次、输错 6 次就作废——它等价于「人正站在那台机器前面点了一下同意」。
换回来的仍然是那台机器自己的 token，**没有造一个跨机的万能钥匙**。
这条边界很重要：`/api/peer/exec` 认的还是目标机的 token，跟平时访问它完全一样。

**为什么不直接开个公共 RPC。** 因为一旦有了"可以匿名执行工具"的口子，
整个沙箱和审批体系就都是装饰。所以公开的只有一个只读探活（不含凭据）
和一个一次性码兑换，其余全在鉴权后面。

**拒绝递归。** `/api/peer/exec` 不接受 `peer_call`。否则 A 让 B 干活、B 又转回 A，
一个请求能在两台机器之间来回弹到栈溢出。这类"能力接口"一定要显式禁止自我引用。

## 第四轮实测踩到的坑（做局域网互认）

**16. 两个实例抢同一个 UDP 端口，以为会报错，其实静默丢包**
HTTP 端口撞了会 bind 失败并给出提示，UDP 组播端口撞了不一定——
没有 `SO_REUSEADDR` 时第二个 bind 直接失败；有它但没有 `SO_REUSEPORT` 时，
Linux 上多播成员关系可能只挂在其中一个 socket 上，表现是"有时能发现、有时不能"。
现在两个都设。Windows 上实测过同机双实例互见；Linux 侧同一段代码会走 `SO_REUSEPORT`，
但这一条**还没在真 Linux 上复验**（WSL 那台当时没开），记在这里免得当成已验证。

**17. 监听 `127.0.0.1` 时，发现得到、连不上**
默认配置是只监听回环（安全优先）。此时组播照发，别的设备能"看见"你，
但配对时连 `192.168.x.x:8787` 会 10061 拒绝——因为你根本没在那个网卡上监听。
这不是 bug，是默认值和安全策略的必然结果，所以启动时会把这句话打出来：
`注意: 只监听回环，别的设备连不上；跨设备请加 --host 0.0.0.0`。
**"能被发现"和"能被连接"是两件事**，配置界面里也得能看出这个区别。

**18. 系统代理会把内网请求打回 502**
开了代理的机器上，`urllib` 默认走 `HTTP_PROXY`，于是 `http://192.168.1.20:8787`
被送去代理服务器，代理当然连不上内网，返回 502。
`llm.py` 早就踩过这个坑，这次在 `peer.py` 里复发，处理方式一样：
内网地址一律 `build_opener(ProxyHandler({}))` 直连。

**19. 停掉发现线程 ≠ 可以重启发现线程**
第一版 `stop()` 只置了 `_stop` 标志。于是设置页改个设备名，热重启时旧线程
还在 `recvfrom` 上阻塞，新线程已经绑好端口——两个线程抢同一个 socket 收包。
更糟的是：如果把 socket 关掉但线程的循环条件已经复位，`OSError` 会走 `continue`，
变成**空转死循环**。
现在 `stop()` 真的关 socket，`_listen` 持有局部引用并在 `OSError` 时无条件 `break`。
一句话：**能停的线程，必须能确定地退出，而不是"大概会退出"**。

**20. 本机回环免签，让"这个接口需要 token 吗"测不出来**
写了个断言「匿名调 `/api/peer/exec` 应该 401」，结果 200——因为测试从 `127.0.0.1` 发，
而本机免签是开着的。断言本身没错，测法错了。
这类鉴权断言只有在**关掉回环豁免**或**从非回环地址发起**时才有意义。
现在挪到"关掉豁免之后"那一段里测，并且真的从 `192.168.1.47` 走了一遍完整配对
（返回 401 而不是超时，正好证明防火墙放行、TCP 通、只是缺 token）。

## 多语言：为什么 key 是中文原文

翻译系统最容易做错的两件事，这里都提前避开了。

**第一件：到处自动替换文本节点。**
听起来很美——遍历 DOM，见到匹配的字符串就换掉。试过，很快崩：
文件管理器里一个**名叫「图片」的文件夹**会被翻译成 Pictures，
终端里 `ls` 的输出会被改写，用户自己起的文件名也会被换掉。
现在的规则是：翻译只发生在**代码里显式调 `t()` 的地方**，以及标了 `data-i18n*` 的静态节点。
多写几个 `t()` 的代价，远低于"AI 把用户的文件名改了"的代价。

**第二件：造一套键名。**
`app.files.title` 这类键名要求维护一张对照表，改一处文案要改两处，
而且贡献者必须先读代码才知道 `dlg.del.confirm` 到底长什么样。
这里的 key 就是中文原文：`{"文件": "Files"}`。翻词典的人不需要碰代码，
改文案时 key 跟着变、旧条目会被 `i18n_check.py` 判成孤儿——**强制你一起改**，这反而是好事。

三级回落：当前语言 → 英文 → 中文原文。第二级是为了避免"德语气泡里蹦出一句中文"，
第三级是为了避免空白。占位符 `{n}` `{name}` 两边必须一致，由脚本机械校验——
这条最容易错，而且错了不会报错，只会在界面上显示字面量 `{n}`。

### 语言怎么定，以及为什么首屏不等 IP

优先级：用户显式选择 > `Accept-Language`（按 q 值）> IP 归属地 > 默认英文。

IP 查询要走外网，最坏情况几秒。如果放在首屏链路里，用户看到的就是几秒白屏。
所以分成两段：`init()` 只查本地存储和 `GET /api/i18n`（服务端不查 IP，只回浏览器语言），
首屏画完之后 `refineByIP()` 再去问 `GET /api/geo`，只有在"判定结果确实不同"时才 reload 一次。

防死循环用的是 `sessionStorage` 里的一次性标记：重载后如果又不一致，就不再重载。
没有这个标记，一台上网出口 IP 与浏览器语言不一致的机器会无限刷新。

### 第五轮实测踩到的坑（多语言）

**21. 用正斜杠传 `--user-data-dir`，Chrome 会假装启动然后立刻退出**
CI 机器上界面测试突然全挂，报"调试端口没起来"。加了 `--enable-logging=stderr` 才看见
`ProcessSingleton.NotifyResult = 2`——Chrome 把命令**转发给了已经在运行的浏览器**，
然后自己以退出码 21 退出，一句话不说。原因是 `--user-data-dir` 的路径被写成
`C:/Users/...` 这种正斜杠形式时没有生效，Chrome 回落到默认配置目录，撞上用户正开着的 Chrome。
教训：**给 Windows 传路径就老老实实用反斜杠**；测试里还要在启动前清掉自己那份
profile（上一轮被 kill 留下的 `SingletonLock` 会让下一次启动同样"转交"出去）。

**22. 代理会把 `127.0.0.1` 也送进代理服务器**
开发机上 `http_proxy=127.0.0.1:52086`、`no_proxy` 是空的，于是测试里
`urllib.open("http://127.0.0.1:9333/json/list")` 也走代理，代理连不回本机，
表现就是"Chrome 没起来"。同一个坑在 `llm.py`、`peer.py`、`geo.py` 里都踩过。
现在测试脚本开头统一把 `127.0.0.1`/`localhost` 塞进 `no_proxy`，
并用 `build_opener(ProxyHandler({}))` 直连。**回环地址永远不该经过代理。**

**23. handler 不读 body，长连接就被毒死了**
设备页每秒轮询 `/api/sys/info`，服务端日志里时不时冒出一条
`501 Unsupported method ('{}GET')`。根因：前端统一以 `{}` 作 body 发 POST，
而 `POST /api/peer/code` 不需要参数，从来没读过 body。HTTP/1.1 是长连接，
那几个字节留在 socket 缓冲里，被当成下一个请求的请求行。
修法不在那个接口上补一句 `read_json()`，而在分发层统一收尾：`_dispatch` 记下
`Content-Length`，路由处理完（含异常路径）在 `finally` 里把没读的 body 吃掉。
**任何一个"参数可选"的接口都可能踩这个坑，所以只能在这一层修。**
回归断言也加了：同一条连接上 POST 带 body、紧接着 GET，两个都得是 200。
